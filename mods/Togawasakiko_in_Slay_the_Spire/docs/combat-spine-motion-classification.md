# 战斗 Spine 运动责任分类规范

日期：2026-06-13

## 一 目的

本文件用于先冻结“哪些部件需要自己动，哪些只是跟着大块部件动”，再进入正式分层绘制。

核心原则：

- 不是所有可见物件都要拆成独立 Spine 部件。
- 是否拆分首先取决于运动责任，其次才是遮挡、接缝和材质管理。
- 跟随同一个大骨骼、不会相对运动的小装饰，默认合并进大块图层。
- 单独 slot 不等于单独运动；overlay 可以只跟随父骨骼。

## 二 运动责任分类

### A 主动受控层

定义：

- 有独立 bone。
- 动画里会被关键帧、IK、pose 切换或动作曲线直接驱动。
- 必须拆成独立图层或独立附件。

典型对象：

- 头部相对颈部转动
- 上臂、前臂、手
- 大腿、小腿、脚或靴子
- 攻击动作里伸出的左臂与指向手势

交付要求：

- 必须有足够的关节隐藏重叠区。
- 不能画木偶球形关节。
- 不能只给可见边界，必须补出被袖口、手套口、裙摆遮住的进入段。

### B 次级动态层

定义：

- 不一定手动逐帧控制，但会有物理、链式骨骼、mesh 形变或延迟摆动。
- 必须拆成独立图层。
- 会响应 A 类主动受控层和躯干动作的惯性，不是孤立循环摆动。

典型对象：

- 双马尾链条
- 前发、侧发、后发摆动层
- 外裙、内裙、后裙摆
- 后腰大蝴蝶结
- 可独立漂浮的金色刺环

交付要求：

- 根部必须藏在发带、头部、腰封或外裙下。
- 长条形部件必须分段或提供可 mesh 变形区域。
- 大幅摆动部件保留比刚体更大的重叠区。
- 需要支持两种幅度：站立时小幅呼吸 / 身体晃动响应，攻击甩手时更大幅度的滞后和回弹响应。

### C 被动跟随大块层

定义：

- 自己没有独立运动方程。
- 但因为跟随的大骨骼不同，需要跟着对应大块移动。
- 可以是独立图层，也可以直接并入该大块图层。

典型对象：

- 红色袖子跟随上臂。
- 手套跟随手。
- 靴子跟随小腿或脚。
- 颈部跟随头/胸之间的简单连接。

交付要求：

- 如果它跟随的父骨骼不同于相邻身体区域，就应拆。
- 如果它和相邻区域始终同骨骼、同变形、同遮挡顺序，则合并。

### D 遮挡 / 装饰 overlay

定义：

- 通常不需要独立运动。
- 单独保留只是为了遮挡顺序、接缝隐藏、材质替换、特效挂点或后续调试。
- 父骨骼跟随 `torso`、`chest`、`head` 等大块。

典型对象：

- 束腰
- 胸口蓝宝石
- 胸前黑色领结 / 蝴蝶结
- 发带蝴蝶结
- 靴子金色鞋头，如果不需要单独高光

交付要求：

- 默认合并进父级大块，除非遮挡顺序或接缝确实要求单独 slot。
- 如果单独保留，必须在档案里标记为 `overlay_only`，不得误配独立运动。

### E 合并进主体层

定义：

- 不需要独立运动。
- 不需要独立遮挡。
- 不需要独立材质、特效或换装。
- 直接画在主体层里。

典型对象：

- 同一块布料上的缝线、纽扣、花纹。
- 束腰上的扣眼和绑带，如果束腰并入躯干。
- 靴子上的固定金属件，如果靴子整体跟随脚。

### F 参考 / 废弃层

定义：

- 只用于提示词、对齐、风格参考或验证流程。
- 不进入正式 Spine 源图。

典型对象：

- 矩形框标注图。
- 自动抠图产生的脏 workdraft。
- 独立正视图生成件。
- 只用于测试贴合准则的束腰样张。

## 四 生成 / 抠图优先级

第一优先级：A 和 B。

- 这些层决定动画质量。
- 必须先设计关节、根部重叠和运动范围。
- 生成时要服务于骨骼运动，不是服务于静态展示。

第二优先级：C。

- 这些层自己不动，但跟随的父骨骼不同。
- 要确保接缝能被袖口、手套口、靴口、裙摆自然遮住。

第三优先级：D。

- 先判断能否合并。
- 只有确认遮挡顺序、特效挂点或调试需要，才单独生成。

默认不做：E 和 F。

- E 直接画进主体层。
- F 只保留为参考或流程证据。

## 五 当前建议的正式制作顺序

1. 左臂攻击链：`arm_l_upper_sleeve`、`arm_l_forearm`、`hand_l_glove_point`
2. 右臂抱胸 idle 链：`arm_r_upper_sleeve`、`arm_r_forearm`、`hand_r_glove_idle`
3. 头部与前发：`head_face`、`hair_front_bangs`、`hair_side_lock_*`
4. 双马尾链条：`hair_twin_tail_*`
5. 裙摆层：`skirt_outer_*`、`skirt_inner_cream_*`、`skirt_back_long_black`
6. 腿与靴：`leg_*`
7. 躯干主体：`body_torso_base`，并决定束腰是否合并
8. overlay：`body_chest_bow`、`body_blue_jewel`、`hair_ribbon_*`、`fx_thorn_halo`

束腰目前不作为优先正式拆件对象。它只保留为贴回准则样张，用来验证源图轮廓裁切和组合预览流程。

## 六 头发物理联动计划

头发属于 B 类次级动态层，重点不是“自己随机飘”，而是对身体和左臂攻击动作做有物理感的二级响应。

### idle / relaxed

- 身体有小幅上下和左右晃动时，头发跟随但略滞后。
- 刘海和侧发振幅最小，主要用于表现呼吸和轻微身体弹动。
- 后发和双马尾振幅更明显，但不能盖过站姿主体。
- 目标观感是稳定、克制、有重量感，而不是持续大幅飘动。

### attack

- 左臂从镜头外侧上抬并直臂斜上 45 度指向怪物侧时，身体和肩部产生瞬间加速度。
- 头发不应和手臂同步到位，而应先因惯性向相反方向滞后，再跟随身体方向过冲，最后回弹收束。
- 双马尾、后发下段、侧发末端是主要响应层。
- 刘海只做小幅延迟，不应遮挡面部表情和视线。
- 攻击结束后，头发应有 `1-2` 次衰减回弹，幅度明显大于 idle，但不能长时间拖尾影响下一张牌动作。

### 影响层级

响应强度从高到低：

1. `hair_twin_tail_*`
2. `hair_back_mass`
3. `hair_side_lock_*`
4. `hair_front_bangs`
5. `hair_ribbon_*`

发带蝴蝶结默认跟随头部，不作为主要物理层；如果后续效果需要，可以给很小的被动回弹。
