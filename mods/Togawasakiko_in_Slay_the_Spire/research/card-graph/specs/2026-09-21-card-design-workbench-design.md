# 卡牌设计工作台设计规格

日期：2026-09-21。
状态：用户已认可功能方向、“本机服务 + 项目文件保存”及本书面规格；实施计划待审核，尚未实现。
范围：扩展既有 `research/card-graph/`，不重建游戏项目。

## 1. 目标与边界

把已有的卡牌关系浏览器扩成可自行构思、保存、比较和纳入研究的设计工作台。
用户应能区分各种关系、直接查看描述中提及的牌、上传卡图并编辑完整草案，
再查看该草案与整个现有卡池的潜在联系，决定是否纳入全局提案。

已确认：

- 关系线同时通过颜色和形状区分，不能只靠箭头或灰度。
- 卡名引用支持悬停效果预览和点击跳转。
- 编辑名称、费用、卡图、基础/升级效果、类型、关键词、来源、品质等。
- 草稿可以试放入全图；好创意可以提交到全局研究。
- 服务只运行在本机，草案与上传图片写入项目研究目录。
- 本轮不生成C#、Harmony补丁、游戏资源包，不安装mod，不启动Godot/Steam/游戏。

研究中的“纳入全局”不等于已实现、不等于平衡已通过、不等于Git提交或远端发布。
现有72张已实现卡与3个固定研究提案仍是只读基线；新草案不能覆盖这些节点。
源码基线继续固定为0.2.3 / `057b6396`，不从脏的共享游戏源码自动重建。

## 2. 选定方案

保留原生HTML/CSS/JavaScript、已固定版本的Cytoscape与Lucide，增加小型本地服务。
采用Python 3标准库HTTP服务与JSON文件存储；Pillow仅用于验证上传图片可解码及尺寸。
不引入数据库、账号、云服务或模型API。运行环境与启动方式在交付说明中给出。

相较纯浏览器存储，项目文件更适合长期维护、备份与后续代码会话读取。
相较完整Web框架或数据库，这一规模无需额外部署与迁移体系。
不通过浏览器任意文件写权限接触其他项目目录。

原来的 `file://.../index.html` 仍可作为只读浏览方式；编辑、保存、上传等操作仅在本机服务模式启用。
文件直开仅显示原有固定基线；新草案及纳入的提案通过服务读取，日常工作入口改用本地HTTP地址。
若服务不可用，明确显示离线/未保存状态，不能把浏览器内存里的内容宣称已落盘。

## 3. 页面与主要流程

沿用当前卡牌目录、图谱和详情布局；增加“图谱”和“草案”视图以及新建入口。
不增加介绍页，打开后直接可分析卡牌。桌面编辑区采用表单与实时预览并排，小屏纵向排列。

### 3.1 创建与保存

可从空白创建，也可复制既有卡牌/固定提案/自己的草案作为新设计。
复制生成独立ID，保留来源引用，不改原卡、不自动复制“已确认关系”的审核状态。

编辑包含：

| 内容 | 约束 |
| --- | --- |
| 名称 | 必填；同名允许，但显示来源及ID后缀以区分 |
| 基础费用、升级费用 | 非负整数0至99或X；升级留空表示费用不变 |
| 卡牌类型 | 攻击、技能、能力、诅咒，与当前图谱已知类型一致 |
| 品质 | Basic/Common/Uncommon/Rare/Ancient/Token/Event |
| 拟定来源 | 主卡池、压力衍生、事件、遗物授予、其他特殊来源；与草稿生命周期分开 |
| Song身份 | 独立开关；只描述拟议身份，不表示已加入游戏Song登记表 |
| 基础/升级关键词 | 可独立配置，支持升级增删；已有词条用多选，自定义词条只作研究文字 |
| 基础效果、升级效果 | 基础必填；升级可声明不变，不从自然语言猜升级运算 |
| 机制信息 | 产出、消耗、读取、触发、时点、对象和限制；用于关系建议 |
| 卡图 | 可缺省；本地上传、替换或解除关联，缺图不阻止保存 |
| 设计备注 | 动机、风险、原作关联、暂定数值说明 |

费用用输入/步进与X模式，类型等用选项菜单，Song等用开关，关键词用多选，工具命令使用Lucide图标与提示。
卡面预览保持固定比例，文字可换行；不把长效果挤进固定高度导致溢出，也不按屏幕宽度缩放字号。

草稿允许内容未填完时保存；“纳入全局”要求名称、费用、类型、品质、来源、基础效果完整且引用有效。
提供显式保存，编辑后延迟自动保存；两者使用相同的验证与版本检查。
显示保存中、已保存、失败、冲突、未保存五类状态。关闭/离开存在未保存内容时提示，不静默丢弃。

### 3.2 试放、纳入与撤回

流程：编辑草稿 → 试放图谱 → 检查/编辑关系 → 纳入全局提案。

- 试放只影响当前预览，默认包含所选草稿及其建议边，不污染全局提案集合。
- 纳入时保存草案当前版本的快照及已确认关系；仍标“未实现提案”。
- 已纳入的设计继续编辑时，草稿与已纳入快照并存；全局使用上一快照，试放使用当前草稿，同一视图不画两个相同ID节点。
- 再次纳入替换该提案快照，并列出相较上一版的字段和关系变化。
- 撤回仅取消全局快照，保留草稿、图片和可恢复历史。
- 归档先撤回再隐藏草案，可从归档视图恢复；不在首版提供不可恢复的批量删除。

已有固定提案依旧可查看及复制，不因服务启动自动转成用户已认可设计。

## 4. 关系的视觉编码

每类关系使用独立的颜色、线型和端点组合，图例、详情列表和图中保持一致。
建议的视觉映射如下；实施时只使用固定Cytoscape版本确认支持的样式。

| 关系 | 色系 | 线型 | 目标端形状 |
| --- | --- | --- | --- |
| 资源供给 | 青绿 | 实线 | 三角 |
| 效果收益 | 蓝 | 实线 | 菱形 |
| 牌序编排 | 金黄 | 长虚线 | 三角 |
| 重复打出 | 紫红 | 短虚线 | V形 |
| 生成候选 | 青蓝 | 点线 | 圆形 |
| 资源取舍 | 橙 | 长虚线 | 菱形 |
| 流程冲突 | 红 | 实线 | 横杠 |

不能把所有提案边重新覆盖成灰色。关系语义决定线样式；“建议/已确认/涉及提案”的状态通过透明度、选择高亮与详情标记表达。
选中一条边时突出其端点和标签，淡化无关边，详情显示方向；反向和同端点不同关系不能被合并掉。
全局仍避免同时堆叠全部卡名。图例可直接筛选，鼠标、键盘和触摸均有等效入口。
颜色不是唯一编码；也不以红色默认表示某张卡“不值得使用”。

## 5. 卡牌引用与预览

卡牌详情、边的条件/解释、设计备注均支持卡牌引用。
新输入通过 `@` 搜索选择卡牌，以稳定ID保存，不依赖未来名称不变。
正文采用受控引用标记并按文本渲染，不允许任意HTML或脚本。

既有文字使用经过维护的名称/别名字典补充引用；优先长名称、中文正式名、明确类名。
“攻击”“防御”“颜”等有歧义的通用词不得盲目链接；无法确定时保持纯文本，并在详情提供明确的关联卡牌列表。
不会声称已经自动理解每段自然语言中所有提及。

鼠标悬停或键盘聚焦显示浮层：卡图、名称、类型/费用、基础效果、升级效果与实现状态。
浮层可停留阅读，限制在视口内；Escape关闭，点击卡名跳转。触屏点击先预览，提供显式进入详情命令。
保留返回栈，返回原关系时恢复选择、筛选与图谱视口，不迫使用户重新寻找那条边。
引用指向已归档草稿时显示归档状态及只读预览；无效ID显示失效标记，不能无声跳到同名另一张牌。

## 6. 关系建议与人工审核

首版是可解释的规则辅助，不是战斗模拟器或自然语言AI。
自由效果描述不会被当作代码执行，也不会仅靠同标签自动宣称协同成立。

### 6.1 机制档案

为已有72张卡整理显式机制档案，保持与当前源码证据的连接。
记录产出/消耗/读取的资源、事件触发、目标归属、时点、次数上限、基础/升级适用范围。
没有可可靠结构化的特殊效果要显式标为人工分析项，不遗漏节点或伪造匹配。
用户通过同一组结构化控件描述草稿；自由关键词不自动进入建议规则。

首版覆盖现有系统的关键关系：

- 压力供给、读取和消耗，存量门槛与兑换之间的争用。
- 格挡获取与支出、生命损失与治疗，区分资源当前值与累计历史。
- 弃牌、消耗、打出、虚无四类事件；消耗自身与消耗材料分开。
- 攻击与力量/自卑/多段反应，重放时重新支付资源的风险。
- Song打出、生成/检索候选资格、牌序和类型交错；类别身份不等于已接入游戏注册。

规则匹配兼容的资源/事件两端，生成方向、关系类型、理由和必要条件。
默认比较全部72张已实现牌与具有机制档案的已纳入提案；未纳入的其他草稿不自动混入，当前试放草稿例外。
普通抽牌不向每张卡拉边；共同的Song标签也不产生全连接。
对需要多步状态、未知时序或外部原版牌的结论标记边界，不自动补全假设。

### 6.2 建议与确认分离

建议显示规则ID、对应档案字段、已有牌证据及条件，不输出虚构的强度分数或概率。
建议默认只用于试放；可逐条接受、修改或拒绝，也可手动连边。
手动边必须选择两个有效端点、方向、关系类型，并填写成立条件与解释；允许明确审核的自环。

涉及草案的边，即使人工确认，也只是“该设计成立时的预期关系”，不是当前游戏已验证效果。
确认记录绑定两端机制版本及使用的基线档案版本。修改费用/类型/品质/来源/效果/关键词/机制等会要求重新审核受影响关系；
只改名称或卡图不使机制审核失效。更新纳入快照前，必须处理待复核关系，可选择移除而非强行接受。
另一提案更新后导致的旧关系标记待复核，不继续作为已确认边展示；不悄悄删除用户写的理由和条件。
被拒绝建议按规则与端点记录；相关机制变化后可重新显示为新候选，不默默覆盖人工编辑。
无匹配时显示“未找到可自动建议的关系”，不解释为没有任何潜在配合。

## 7. 文件、模块与数据契约

下列为拟新增/调整的设计结构，不是已存在API的声明。

| 区域 | 职责 |
| --- | --- |
| 现有catalog、families、graph.json/graph-data.js | 保持版本化只读基线与离线查看能力 |
| `mechanic-profiles.json` | 人工审查的基础牌机制档案及来源 |
| `workspace/workspace.json` | 用户草案、全局快照、关系审核、归档状态和revision |
| `workspace/uploads/` | 经验证的用户卡图，以服务端生成的ID保存 |
| `workspace/history/` | 写入前的有界恢复备份，不作为活动数据源 |
| `server.py`及小型存储模块 | 静态服务、限定的读写入口、校验、原子保存与版本冲突 |
| 前端草案/引用预览/建议模块 | 各自独立，现有graph.js负责图谱整合，不堆成单个巨文件 |

工作区文件带独立 `schema_version` 和递增 `revision`；不能修改既有graph的schema来伪装成新游戏基线。
草案使用服务端生成的 `draft:<uuid>` 稳定ID；显示名字、拟定来源、生命周期、是否Song分开存储。
每条草案包含可编辑版本、可选全局快照和来源引用；关系也使用独立ID，不按显示文字当主键。
所有文本长度、枚举、数字范围、数量和引用均在服务端校验，不能只相信前端控件。

服务向UI返回“只读基线 + 用户工作区”；图谱在内存合成，不把用户草案写回生成的graph.json。
现有子图导出保留；新增工作区JSON导出包含草案、快照、已确认/拒绝关系和相对图片引用。
上传图片与JSON同在项目中，完整备份应包含两者；不宣称单独JSON包含图片像素。
首版不实现任意ZIP导入、旧版本复杂迁移或自动Git操作。

## 8. 持久化与失败处理

- 单实例写入锁，写入临时文件后原子替换；成功响应只在落盘完成后返回。
- 保留最近20份工作区备份；图片不自动清理，避免旧快照恢复后缺图。
- 客户端提交读取时的revision，版本过期返回冲突而不是最后写入者覆盖。
- 冲突时保留本页编辑，可下载本地副本并重新加载；不自动执行不可解释的文本合并。
- 上传先验证并保存，草案只存图片ID；上传失败不清空旧图。
- 自动保存只在内容变更且请求可串行处理时执行，离线不无限重试。
- 数据文件损坏时拒绝写入并指出恢复入口，不用空工作区覆盖原文件。
- 不认识的schema版本只读报错，不能猜格式继续写入。

## 9. 本机安全边界

服务仅绑定 `127.0.0.1`，不监听局域网地址。启动优先选固定端口，已被占用则换空闲端口并报告实际URL，不结束其他进程。
静态文件只服务白名单；不以整个仓库或用户目录作为静态根。
既有卡图通过已核验节点ID到允许资产目录的映射提供，不接受客户端任意路径。

写请求检查实际Host/Origin及启动会话令牌，不开放CORS；防止其他网页向本地服务提交草稿或文件。
仅接受规定的JSON请求与图片类型，设置请求体上限，不提供Shell、源码执行、任意文件读写或外网代理接口。
上传支持PNG/JPEG/WebP，单张不超过10MiB、3200万像素，以真实解码为准；不接受SVG、HTML或仅修改后缀的文件。
不以用户文件名生成磁盘路径，不允许 `..`、编码路径穿越或symlink越出允许根。
图片不上传到外部服务；原样保存通过验证的图片，不自动裁剪、改画或生成素材。

## 10. 验收

数据/服务测试：

- 草稿创建、保存、重载后字段与图片关联一致，基础与升级关键词可不同。
- 纳入、继续编辑、重新纳入、撤回、归档、恢复的状态正确，旧快照不会被未完成编辑污染。
- 72张已实现牌、3个固定提案及游戏源码/资源不被保存接口改写。
- 并发revision冲突、磁盘写失败、损坏JSON、未知schema均不丢失原数据。
- 上传伪装类型、超限图片、路径穿越、错误Origin/令牌等被拒绝。
- 规则覆盖实际旧牌例子，同时测试假关系排除：主动消耗不等于打出、普通入弃牌堆不等于弃牌、非Song不减少两轮月亮费用。
- 草案改机制后旧确认边需复核；共同标签不会生成无条件全连接。

界面测试：

- 在桌面与手机查看七类边，颜色/线型/形状和图例一致，提案状态不遮掉关系语义。
- 悬停、键盘聚焦、触摸预览及卡牌跳转/返回可用，浮层不被裁切或遮住关键操作。
- 完整走通新建、上传、基础/升级编辑、保存重载、试放、关系审核、纳入及撤回。
- 编辑失败/冲突时表单内容仍在，状态提示与实际磁盘结果一致。
- 检查截图、画布非空像素、文字溢出与关系选择；不以“有节点数”替代可读性验证。
- `file://`只读模式能继续浏览，服务模式使用报告的本地URL。

游戏内实测、平衡测试、补丁生成和正式卡牌实现均不属于本规格验收。
